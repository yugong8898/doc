# 测试与 Bug 循环

## 一、为什么需要测试与 Bug 循环

### 当前问题

- 测试用例和需求对不上，不知道测什么
- 测试失败后直接改代码，不判断根因
- Bug 修复后只测原问题，不做回归
- AI 推导的用例被当成正式测试结论
- 环境问题被误判为实现缺陷

### 测试与 Bug 循环解决

- 测试用例与需求双向对应
- 测试失败后按根因分类
- 根据根因决定回退阶段
- Bug 修复后完成受影响回归
- 正式测试和自测结论明确分离

## 二、测试用例分类

### 按来源分类

| 来源 | 说明 | 验收效力 |
|---|---|---|
| QA 提供 | QA 或产品提供的正式测试用例 | 正式验收依据 |
| AI 推导 | AI 根据需求生成的补充用例 | 开发自测依据，待确认 |
| 手工补充 | 开发根据边界场景补充的用例 | 开发自测依据，待确认 |

**重要**：AI 推导用例必须标注：

```text
用例来源：AI 推导
用例状态：待 QA/产品确认
用途：开发自测依据
结论：不代表正式验收通过
```

### 按类型分类

| 类型 | 说明 | 示例 |
|---|---|---|
| 主流程用例 | 验证核心业务流程 | 编辑页修改费用后保存 |
| 边界用例 | 验证边界条件 | 费用为 0、负数、超长 |
| 异常用例 | 验证异常处理 | 保存接口失败、网络超时 |
| 权限用例 | 验证权限控制 | 无权限用户禁止操作 |
| 状态用例 | 验证状态流转 | 已完成状态禁止修改 |
| 多端用例 | 验证多端差异 | PC、H5、小程序、APP |
| 回归用例 | 验证原有功能 | 修改后原有字段仍正常展示 |

## 三、测试覆盖对齐（阶段 5）

### 覆盖矩阵

测试基线与覆盖对齐阶段必须检查三个方向：

```text
需求 → 测试用例
测试用例 → 需求
测试用例 → 代码实现
```

### 覆盖矩阵示例

```markdown
| 需求规则 | 对应测试用例 | 代码实现 | 覆盖状态 |
|---|---|---|---|
| R-001：编辑页允许修改费用字段 | TC-001, TC-003 | edit.vue:120 | 已覆盖 |
| R-002：已完成状态不可修改 | - | view.vue:88 | 未覆盖，需补充用例 |
| R-003：保存失败时保留用户输入 | TC-002 | api.js:45 | 部分覆盖，缺接口失败场景 |
| R-004：移动端同步展示该字段 | TC-005 | app/edit.vue:88 | 已覆盖 |
| R-005：费用为负数时标红提示 | TC-004, TC-006 | edit.vue:150 | 已覆盖 |
```

### 覆盖缺口处理

| 覆盖问题 | 处理方式 |
|---|---|
| 需求有但测试用例没有 | 补充用例或明确不测试的原因 |
| 测试用例有但需求没有 | 确认是否超出范围或需求遗漏 |
| 测试用例有但代码没有实现 | 实现缺口，回退到阶段 3 |

## 四、测试执行与结果记录（阶段 6）

### 测试用例状态

每条测试用例只能处于以下状态之一：

| 状态 | 含义 | 下一步 |
|---|---|---|
| 未执行 | 尚未执行 | 执行测试 |
| 通过 | 执行通过 | 继续下一条 |
| 失败-待修复 | 执行失败，需要修复 | 记录 Bug，分类根因 |
| 阻塞-待确认 | 环境或数据问题，无法执行 | 解除阻塞后重新执行 |
| 不适用-已说明 | 该用例不适用当前场景 | 说明原因 |

### 测试结果记录

```markdown
| 用例编号 | 用例描述 | 关联需求 | 执行结果 | Bug 编号 | 备注 |
|---|---|---|---|---|---|
| TC-001 | 编辑页修改费用后保存 | R-001 | 通过 | - | - |
| TC-002 | 已完成状态禁止修改 | R-002 | 失败-待修复 | BUG-001 | 已完成状态仍可修改 |
| TC-003 | 保存失败后重新进入保留输入 | R-003 | 通过 | - | - |
| TC-004 | 移动端编辑页修改费用后保存 | R-001, R-004 | 阻塞-待确认 | - | 测试环境不可用 |
```

## 五、Bug 分类与回退

### Bug 根因分类

测试失败后，不能直接改代码，必须先判断失败类型：

| 失败类型 | 判定 | 回退位置 | 处理方式 |
|---|---|---|---|
| 需求偏差 | 实现与已确认需求不一致 | 阶段 0 | 更新需求基线，重新分析 |
| 方案遗漏 | 需求有，方案未覆盖 | 阶段 2 | 补充技术方案，重新实现 |
| 实现缺陷 | 方案正确，代码错误 | 阶段 3 | 修复代码，重新审查 |
| 测试问题 | 用例步骤或预期有误 | 阶段 5 | 修正测试基线 |
| 环境问题 | 接口、数据、权限或环境阻塞 | 不回退 | 标记阻塞，等待确认 |

### Bug 分类示例

#### 示例 1：需求偏差

```text
Bug：已完成状态仍可修改
预期：已完成状态不可修改
实际：已完成状态仍可修改
根因分析：需求理解错误，认为只有"已取消"状态不可修改
根因分类：需求偏差
回退阶段：阶段 0
处理：更新需求理解，重新分析影响范围和技术方案
```

#### 示例 2：方案遗漏

```text
Bug：保存接口失败后页面无提示
预期：保存失败时提示用户
实际：保存失败时无任何提示
根因分析：技术方案中只考虑保存成功场景，遗漏异常处理
根因分类：方案遗漏
回退阶段：阶段 2
处理：补充异常处理方案，重新实现和测试
```

#### 示例 3：实现缺陷

```text
Bug：移动端费用输入后未保存
预期：移动端和 PC 端行为一致
实际：移动端点击保存后数据未提交
根因分析：移动端代码遗漏调用保存接口
根因分类：实现缺陷
回退阶段：阶段 3
处理：修复移动端代码，重新审查和测试
```

#### 示例 4：测试问题

```text
Bug：费用为 0 时保存失败
预期：费用为 0 时可以保存
实际：费用为 0 时保存失败
根因分析：测试预期错误，需求明确费用必须大于 0
根因分类：测试问题
回退阶段：阶段 5
处理：修正测试用例预期
```

#### 示例 5：环境问题

```text
Bug：保存接口返回 503
预期：保存成功
实际：接口返回 503 服务不可用
根因分析：测试环境接口未部署
根因分类：环境问题
回退阶段：不回退
处理：标记阻塞，等待环境恢复后重新测试
```

## 六、Bug 记录

### Bug 记录格式

每个失败用例都必须创建 Bug 记录：

```markdown
## BUG-001

**关联需求**：R-002  
**关联用例**：TC-002  
**严重程度**：P0  
**Bug 描述**：已完成状态仍可修改  
**复现步骤**：
1. 创建一条运单，状态为"已完成"
2. 进入编辑页
3. 修改费用字段
4. 点击保存

**预期结果**：已完成状态不允许修改，保存按钮置灰或点击后提示  
**实际结果**：已完成状态仍可修改，保存成功  
**根因**：需求理解错误，认为只有"已取消"状态不可修改  
**根因分类**：需求偏差  
**涉及文件**：edit.vue  
**修复方案**：更新需求理解，补充状态校验逻辑  
**修复文件**：edit.vue:88-95  
**回退阶段**：阶段 0  
**状态**：已修复待回归  
**修复验证**：
- 原失败用例 TC-002：通过
- 回归用例 TC-007（已取消状态）：通过
- 回归用例 TC-008（进行中状态）：通过
```

### Bug 状态流转

```text
待修复
  ↓
修复中
  ↓
已修复待回归
  ↓
回归通过 → 已关闭
回归失败 → 待修复
```

## 七、Bug 修复循环

### 标准循环流程

```text
执行测试
  ↓
记录失败用例
  ↓
分析根因
  ↓
分类（需求偏差/方案遗漏/实现缺陷/测试问题/环境问题）
  ↓
回退到对应阶段（或标记阻塞）
  ↓
修复或重新评估
  ↓
重新审查（如需要）
  ↓
执行原失败用例
  ↓
执行受影响回归
  ↓
更新 Bug 状态
  ↓
更新追踪矩阵
  ↓
再次执行测试（直到全部通过或明确阻塞）
```

### 循环终止条件

满足以下任一条件时终止循环：

```text
□ 所有 P0/P1 用例通过
□ 所有 P2 用例有处理结论（修复、排期或接受风险）
□ 所有阻塞项已明确，等待解除
□ 同一问题连续两轮修复仍失败（暂停，请求人工决策）
```

### 循环终止保护

当同一问题连续两轮修复仍失败时，不继续无限自动修改：

```text
暂停自动修复
  ↓
输出以下信息：
- 问题现象
- 根因假设
- 已尝试修复方案
- 当前阻塞原因
  ↓
请求人工确认下一步
```

## 八、回归范围推导

Bug 修复后不能只测原问题，还要根据影响范围补充回归。

### 回归范围规则

| 修改对象 | 最低回归范围 |
|---|---|
| 单页面展示 | 当前页面 + 同类查看页 |
| 公共组件 | 所有引用页面 |
| API 封装 | 所有调用方 |
| 金额计算 | 所有金额入口 + 边界值（0、负数、最大值） |
| 权限逻辑 | 有权限和无权限账号 |
| 状态逻辑 | 所有相邻状态 |
| 多端代码 | H5、小程序、APP 对应页面 |
| 条件编译 | 所有受影响平台 |
| 数据流转 | 上下游页面和接口 |

### 回归范围示例

#### 示例 1：修复单页面展示

```text
修改：edit.vue 中费用字段展示逻辑
回归范围：
- edit.vue（当前页面）
- view.vue（查看页）
- list.vue（列表页）
```

#### 示例 2：修复公共组件

```text
修改：components/FeeInput.vue 中费用输入组件
回归范围：
- edit.vue（引用该组件）
- adjust.vue（引用该组件）
- settle.vue（引用该组件）
```

#### 示例 3：修复 API 封装

```text
修改：api/order.js 中保存接口封装
回归范围：
- edit.vue（调用保存接口）
- adjust.vue（调用保存接口）
- app/edit.vue（移动端调用保存接口）
```

#### 示例 4：修复金额计算

```text
修改：utils/calculate.js 中金额计算逻辑
回归范围：
- 所有金额入口（录入、编辑、调整）
- 边界值测试（费用为 0、负数、超大值）
- 精度测试（小数点后多位）
```

#### 示例 5：修复状态逻辑

```text
修改：edit.vue 中已完成状态禁止修改
回归范围：
- 已完成状态（修复目标）
- 已取消状态（相邻状态）
- 进行中状态（相邻状态）
- 待审核状态（相邻状态）
```

## 九、严重程度规则

### P0、P1、P2 定义

| 严重程度 | 定义 | 处理规则 |
|---|---|---|
| P0 | 核心功能不可用、数据错误、安全漏洞、权限绕过 | 默认阻塞交付，必须修复并回归 |
| P1 | 重要功能缺陷、逻辑错误、边界遗漏 | 默认阻塞交付，必须修复并回归 |
| P2 | 样式问题、文案错误、低频边界、体验优化 | 必须有处理结论，再根据影响决定是否阻塞 |

### P2 处理

P2 不能简单写成"不阻塞交付"。如果要遗留，至少需要记录：

```text
□ 问题描述
□ 影响范围
□ 风险评估
□ 后续处理人或归属
□ 后续版本或需求编号
□ 产品或负责人明确接受
```

## 十、测试结论类型

最终测试结论必须明确区分：

| 测试结论类型 | 判定条件 | 交付说明 |
|---|---|---|
| 正式测试通过 | 有 QA 用例，并且 QA 用例全部通过 | 可以正式交付 |
| 开发自测完成 | 无 QA 用例，仅 AI 推导用例通过 | 仅完成开发自测，未获得正式 QA 测试结论 |
| 测试阻塞 | 存在环境、数据、接口、权限或待确认问题 | 无法完成测试，需解除阻塞 |

**重要**：不能把"AI 用例执行通过"写成"正式测试通过"。
