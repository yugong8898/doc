# 最终交付门禁

## 一、为什么需要交付门禁

### 当前问题

- 不知道什么条件下才能交付
- "代码改完"就被认为可以交付
- 测试未完成就宣布完成
- Bug 未修复就宣布交付
- 没有证据证明需求已全部实现

### 交付门禁解决

- 明确交付的必要条件
- 需求、方案、代码、测试和 Bug 全部对齐
- 有完整的证据链和追踪记录
- 不满足门禁条件时不能交付

## 二、最终交付门禁

满足以下所有条件后，才能输出"最终交付"：

### 需求完整性

```text
□ 所有已确认需求均已实现，或有明确排除原因
□ 需求变更已记录并完成影响评估
□ 不存在会影响交付的未确认项
□ 需求基线版本已明确
```

**检查方法**：

- 逐条检查 `R-*` 是否都有对应实现
- 检查需求变更日志是否完整
- 检查是否有未处理的待确认项
- 确认当前需求版本

**不通过示例**：

```text
R-003 在需求文档中，但追踪表中无对应实现
→ 需求完整性不通过
```

### 实现完整性

```text
□ 需求、方案和代码三向一致
□ 所有额外改动均有原因和追踪记录
□ 横向页面、公共组件、接口封装和多端影响已检查
□ 权限、校验、状态和旧逻辑处理已完成审查
```

**检查方法**：

- 检查是否存在"需求有但方案没有"的内容
- 检查是否存在"方案有但代码没有"的内容
- 检查是否存在"代码有但需求和方案都没有"的内容
- 检查横向搜索是否完整
- 检查代码审查是否通过

**不通过示例**：

```text
代码中增加了字段 B，但需求和方案都没有说明
→ 实现完整性不通过
```

### 测试完整性

```text
□ 正式 QA 测试用例全部执行并通过
  或
  没有正式用例时，AI 推导用例的自测性质和风险已明确
□ 每条需求规则都有测试覆盖或明确说明
□ 失败用例已修复并完成原用例和受影响回归
□ lint、类型检查、构建等适用检查已记录结果
```

**检查方法**：

- 检查测试结论类型（正式测试通过 / 开发自测完成 / 测试阻塞）
- 检查覆盖矩阵是否完整
- 检查失败用例是否都已修复并回归
- 检查适用的静态检查是否已执行

**不通过示例**：

```text
TC-002 失败，状态为"待修复"
→ 测试完整性不通过
```

### 缺陷完整性

```text
□ P0/P1 缺陷全部关闭
□ P2 缺陷已修复、排期或明确接受风险
□ 没有未解释的失败、阻塞或遗留问题
```

**检查方法**：

- 检查 Bug 跟踪表中 P0/P1 的状态
- 检查 P2 是否有处理结论
- 检查是否有未分类或未处理的问题

**不通过示例**：

```text
BUG-001（P0）状态为"已修复待回归"，未关闭
→ 缺陷完整性不通过
```

## 五、不满足门禁时的处理

### 输出格式

当不满足交付门禁时，不能输出"已完成"或"可以交付"，必须输出：

```text
【不能交付】

当前状态：阶段 X
阻塞项：
- [ ] 需求完整性：R-003 无对应实现
- [ ] 缺陷完整性：BUG-001（P0）未关闭

下一步：
1. 补充 R-003 的实现
2. 完成 BUG-001 的修复和回归
3. 重新检查交付门禁
```

### 常见阻塞项

| 阻塞项 | 原因 | 处理 |
|---|---|---|
| 需求未实现 | 追踪表中某条 R-* 无对应实现 | 补充实现或明确排除 |
| 待确认项未处理 | 存在影响交付的待确认项 | 确认后更新需求 |
| 测试未通过 | 存在失败用例 | 修复并回归 |
| P0/P1 未关闭 | P0 或 P1 Bug 未修复 | 修复并关闭 |
| P2 无结论 | P2 Bug 无处理结论 | 修复、排期或接受风险 |
| 验证未完成 | 某个阶段验证状态为"待确认"或"阻塞" | 完成验证 |

## 七、交付验收方式

### 用户验收

用户可以按以下方式验收：

1. 检查交付报告中的测试结论类型
2. 检查需求覆盖率是否 100%
3. 检查 P0/P1 Bug 是否全部关闭
4. 检查 P2 Bug 是否有处理结论
5. 检查是否有遗留问题和已知风险
6. 检查验证闭环是否全部通过

### 拒绝交付的情况

以下情况应拒绝交付：

```text
□ 测试结论类型为"开发自测完成"但宣称"正式测试通过"
□ 需求覆盖率不足 100%
□ 存在未关闭的 P0/P1 Bug
□ 存在无处理结论的 P2 Bug
□ 验证闭环有"阻塞"或"待确认"
□ 交付报告缺失
```

## 八、常见错误

### 错误 1：代码改完就宣布交付

**问题**：没有测试、没有审查、没有验证。

**正确**：必须通过全部交付门禁。

### 错误 2：测试未完成就宣布完成

**问题**：测试用例还在执行或有失败用例。

**正确**：所有用例执行完成且通过（或有明确处理结论）。

### 错误 3：把 AI 用例通过当成正式测试通过

**问题**：AI 推导用例不代表正式 QA 验收。

**正确**：明确标注"开发自测完成"。

### 错误 4：P2 Bug 未处理就交付

**问题**：P2 Bug 没有修复、排期或接受风险的结论。

**正确**：P2 必须有明确处理结论。
