## 快速决策参考

### 核心改进

从单向流水线升级为验证闭环：

```
现在：需求 → 方案 → 编码 → 审查 → 提测 → 交付
问题：中途偏差无法及时发现

升级后：每阶段完成 → 对照锚点验证 → 发现偏差 → 修正或回退 → 再验证
效果：每一步都对齐上一步，偏差不传递
```

### 最终采用

```
7 阶段流程
+
每阶段对照锚点回验
+
R-* 需求追踪
+
测试覆盖矩阵
+
Bug 根因分类回退
+
正式测试与自测分离
+
最终交付门禁
```

### 已统一的关键决策

| 决策项 | 结论 |
|--------|------|
| 阶段数量 | 7 阶段（测试基线对齐 + Bug 修复循环拆开） |
| P2 处理 | 必须有修复/排期/接受风险的结论 |
| 工作模式 | 默认逐阶段确认；简单低风险允许自动推进 |
| 追踪表 | 分层策略——所有需求建轻量记录，复杂需求建完整矩阵 |
| 交付报告 | 独立成文件，workflow-state.md 只保留状态索引 |
| AI 推导用例 | 标注"自测依据"，QA 正式用例到位后自动降级 |

### 实施建议

不要一次改完，建议按以下顺序渐进推进：

1. 统一状态、阶段和回退规则
2. 增加统一验证协议
3. 增加 R-* 编号和最小追踪记录
4. 拆分阶段 5（测试基线与覆盖对齐）
5. 增加阶段 6（测试执行与 Bug 修复循环）
6. 增加三种测试结论类型
7. 增加验证证据、范围外改动、回归范围记录
8. 同步更新三端 wlyd-workflow + role-workflow.md
9. 执行三端同步校验
10. 用真实需求试运行，根据实际负担调整
